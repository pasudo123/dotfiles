# PR 작성 규칙

## 원칙
- 길게 쓰지 않는다. 핵심만 3~5줄로 작성한다.
- "무엇을", "왜", "어떻게 확인했는지"만 쓴다.
- 스크린샷/로그는 필요한 경우만 첨부한다.

## 본문 포맷 규칙
- PR 본문에서 `##` 같은 Markdown 헤딩은 사용하지 않는다.
  (GitHub에서 글씨가 크게 보일 수 있음)
- 섹션 구분은 `**요약**`, `**이유**`, `**검증**`, `**참고**` 형태의
  굵은 라벨 + 불릿으로 작성한다.

## CLI 작성 규칙
- `gh pr create` 시 본문은 `--body-file` 사용을 기본으로 한다.
  (`--body` 인라인 문자열은 줄바꿈/기호가 깨지기 쉬움)

## PR 생성 예시
```bash
# 1) 템플릿 파일 작성
cat > /tmp/pr-body.md <<'EOPR'
**요약**
- ...

**이유**
- ...

**검증**
- ...
EOPR

# 2) PR 생성
gh pr create --base main --head <branch> --title "<title>" --body-file /tmp/pr-body.md
```
